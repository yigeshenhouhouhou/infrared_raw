与 0.1.0 / 0.2.0 相同包名与签名，可直接覆盖安装，不需要卸载。

本版没有新增界面功能，也没有刻意改变成像风格。修的是 0.2.0 之后源码与
安装包失配的问题。0.2.0 的 APK 是 12:00 构建的；此后 12:41—12:43 的一次
未完成改造把原生核心改成 29 个参数并引入了 DCP / 3D LUT 代码，同时让源码
不再编译，改造就停在那里。于是磁盘上的 0.2.0 安装包早于源码，无法由当前
源码复现。0.2.1 是第一个与当前源码一一对应的安装包。

修复
  1. 原生核心恢复编译。core.cpp 有两处遗留：局部 static const ColorContext
     缺少显式值初始化；引用了一个该编译单元并不存在的 clip()。
  2. 参数契约恢复。桥接层要求 29 个渲染参数，而 Java 界面仍在发 22 个，
     当前源码若直接打包，每次预览和导出都会抛 "Render settings must
     contain 29 values"。界面现已发送完整 29 项。
  3. 原生默认值锁定到桌面参考实现。此前 v[17]=3、v[22]=2、v[23]=75，
     与桌面 ir_wb_gui.DEFAULTS 不一致，导致同一组参数在手机与电脑上得到的
     不是同一条曲线。现改为 v[17]=1（590 nm 蓝金）、v[22]=0（共用增益
     对数肩部，比例保持）、v[23]=100（完整通道比例）。
  4. 安装包不再携带调试符号。NDK 工具链默认输出 .debug_*，0.2.0 的
     libinfrared.so 里有约 4.9 MB 调试信息，随改造又涨到约 9 MB，APK 因此
     到 6.73 MB。现在打包前用 llvm-strip --strip-all 处理副本（构建树保留
     符号），APK 降到 1.70 MB，.so 从 12.09 MB 降到 2.33 / 2.55 MB。
     已核对两个 ABI 的动态符号表都仍导出 10 个 JNI 入口。

验证（android\validate.py 实测）
  native 核心与桌面 process_array 的浮点对照：18 组参数 / 180 个样本，
    最大绝对误差 8.34e-07（阈值 4e-06）。
  合成 DNG 经 LibRaw 解码，与桌面 tone_map 逐像素一致（≤1/255）。
  真实 Sony NEX-5 ARW 三档解码：1152×768、2304×1536、4608×3072。
  APK 压缩包完整性、classes.dex 头、内嵌 sRGB ICC、arm64 与 x86_64 的
    ELF 机器类型、16 KB LOAD 段对齐：通过。

仍未验证
  没有在安卓真机或模拟器上运行过。上述是同一份 C++ 核心在 Windows 上
  编译并执行的结果，能证明算法一致，不能替代安卓端的文件选择、保存、
  内存占用与机型兼容性测试。首次安装请从半尺寸导入开始试。

不变

  自动白平衡仍是全图统计起点，建议用吸管框中性区域。
  JPG 质量 95、内嵌 sRGB ICC；TIFF、32-bit 浮点底片、批量队列未移植。
  全尺寸导出上限 3600 万像素。
